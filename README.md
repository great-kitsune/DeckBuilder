# DeckBuilder

Grand Archive Utility의 첫 구현은 Windows·Android에서 사용하는 오프라인 카드 DB와 검색이다. Flutter 3.38.7 및 Dart 3.10으로 개발했다.

## PR 실행 파일

각 PR에서 Android APK와 Windows x64 앱을 자동 빌드한다. GitHub에 로그인한 뒤 PR의 **실행 파일 다운로드** 댓글에서 플랫폼을 선택한다. 새 커밋의 두 빌드가 성공하면 댓글 링크도 갱신된다. 포크 PR 등 댓글 쓰기가 제한되는 경우 **Checks → Card catalog** 실행 페이지의 **Artifacts**에서 받는다. 파일은 빌드별로 30일 동안 보관한다.

- **Android** — 다운로드한 ZIP을 풀고 `app-debug.apk`를 설치한다. CI에서 생성한 테스트 서명을 사용하므로 이전 APK와 서명이 다를 수 있다.
- **Windows x64** — ZIP 전체를 한 폴더에 풀고 `deck_builder.exe`를 실행한다. 함께 들어 있는 DLL과 `data` 폴더가 필요하다.

## 개발 환경에서 실행

Flutter와 대상 플랫폼 도구를 설치한 환경에서 실행한다.

```sh
flutter pub get
flutter run -d windows
```

Android는 `flutter devices`에 표시된 기기 ID로 `flutter run -d <기기-ID>`를 실행한다. 테스트는 `flutter test`, 정적 분석은 `flutter analyze`로 실행한다.

## 다운로드와 검색 설정

- 첫 설치는 **카드 데이터 설치**, 설치 후 홈이나 설정에서 **카드 데이터 업데이트**를 누른다. 텍스트 검색은 오프라인에서도 가능하다. Android는 WorkManager, Windows는 별도 작업 스레드에서 설치를 진행한다.
- 썸네일과 상세 이미지는 열람할 때 공식 API에서 받아 캐시한다. 기존 버전에서 내려받은 같은 버전의 파일도 재사용하며, 설정의 **이미지 캐시 관리**에서 용량 확인과 삭제가 가능하다.
- 설정의 **무결성 검사**는 설치한 DB의 구조, 외래 키, 카드·인쇄판과 검색용 데이터, 저장된 공식 이미지 캐시를 확인한다. 설치 때 기록한 목록과 해시로 누락·변경을 확인한다. 이전 버전 설치본은 첫 전체 데이터 재검사 후 증분 기준이 생긴다. 손상된 캐시는 다음 열람 때 다시 받는다.
- **카드 검색 표시 방식**에서 목록 또는 화면 너비에 맞는 썸네일 격자를 고른다. 선택한 방식은 기기에 저장된다.
- 카드 상세의 첫 인쇄판은 API 순서대로 상단에 펼쳐 표시한다. API가 효과 텍스트에 표시한 키워드는 굵게 읽을 수 있다.

## 사용 방법

- 양면 카드의 뒷면과 인쇄판도 독립적으로 색인한다. 공식 목록과 페이지 결과를 UUID로 대조하고 누락된 상세를 개별 조회한다. 임시 SQLite DB 검증이 끝나면 한 트랜잭션으로 적용한다.
- **카드 검색**에서 이름·효과와 필터를 조합한다. 그룹 내 연산은 각각 AND/OR를 선택하고 그룹 간에는 AND를 적용한다. 세트·희귀도는 동일한 후보 인쇄판 집합에서 평가한다. 에디션별 보기로 해당 인쇄판을 확인할 수 있다.
- **스포일러 추가**에서 공개된 정보와 이미지를 등록한다. 스포일러 정보와 사진은 공식 카드와 별도 테이블에 보관한다. 설치와 무결성 검사에서 카드명 및 영문명을 대조하고, 동명 카드는 세트와 수집 번호로 좁힌다. 후보가 하나면 기존 로컬 ID를 공식 UUID에 연결한다. 여러 후보가 남으면 설정의 **공식 카드 선택 대기**에서 확인한다.

공식 데이터는 [Grand Archive Index API](https://api-docs.gatcg.com/)에서 사용자의 요청으로 내려받는다.

## Standard 덱 편집

**덱 → 새 덱**에서 덱을 만들고 Material Deck, Main Deck, Sideboard의 **카드 추가**를 누른다. 검색 결과에서 카드를 누르면 상세를 열고, ＋를 누르면 선택한 구역에 한 장씩 담는다. 필터의 **에디션별 보기**에서 인쇄판을 선택할 수 있다. 일반 검색에서는 첫 인쇄판을 사용한다. 넓은 화면은 검색과 편집을 나란히 표시한다.

각 항목에서 수량을 조절하거나 **구역 이동**으로 일부 수량을 옮긴다. 편집 즉시 기기에 저장하며 덱 목록에서 이름 변경, 복제, 삭제가 가능하다. 카드 DB 재설치 후에도 덱을 유지한다. 스포일러가 공식 카드에 연결되면 수량과 구역을 보존하고, 후보가 여러 개면 덱의 해당 카드에서 후보를 확인할 수 있다.

덱 안의 카드도 설정의 **카드 검색 표시 방식**을 따른다. Main Deck의 카드 추가 화면에는 Reserve, Material Deck에는 Memory 카드가 표시된다. 동명 카드는 인쇄판을 합산해 Reserve는 Main과 Sideboard에 총 4장, Memory는 Material과 Sideboard에 총 1장까지 담을 수 있다. Sideboard에는 Reserve 1장당 1점, Memory 1장당 3점으로 계산한 점수를 표시한다.

### 덱 리스트 내보내기와 불러오기

덱을 열고 우측 상단 **덱 출력 및 검증** 메뉴를 사용한다.

- **덱 리스트 PNG 저장**은 세 구역의 카드를 선택한 인쇄판의 썸네일로 한 줄에 최대 12종류씩 저장한다. 상단에는 덱 이름을 크게 표시하고, 각 구역 제목에 해당 구역의 매수를 표시한다. 머터리얼 덱은 Spirit LV 0 다음에 챔피언 계열을 카드 종류가 많은 순으로, 계열 안에서는 낮은 레벨부터 배치한다. Class에 Mage가 있는 Merlin은 앞선 Mage 챔피언 계열에 이어진다. 나머지 카드는 챔피언 뒤에 배치한다. 각 카드 하단 중앙의 숫자는 해당 구역에 넣은 매수이며 Sideboard 합계에는 점수도 표시한다. 공식 이미지는 캐시를 우선 사용하고 필요하면 API에서 받는다. 스포일러는 등록한 사진을 사용하며 이미지를 읽을 수 없는 카드도 카드명과 매수로 표시한다. Android와 Windows의 파일 저장 창에서 위치를 고른다.
- **Omnidex 형식 복사**는 세 구역별로 수량과 영문 카드명을 복사한다. 같은 구역의 인쇄판은 카드명으로 합산한다. 복사 후 **네**를 누르면 Omnidex를 연다. 스포일러를 포함하면 복사와 공식 검증이 차단된다.
- **Omnidex 공식 검증**은 현재 레시피를 Standard 형식으로 공식 서버에 보내 유효·무효 판정과 오류를 표시한다. 연결 실패나 예상 밖 응답은 미확인으로 표시하며 다시 검증할 수 있다. [공식 API 명세](https://api.gatcg.com/openapi.json)

**덱 → 레시피 불러오기**에서 Omnidex 텍스트를 붙여넣거나 UTF-8 TXT 파일을 열고 새 덱으로 저장한다. 설치된 공식 카드 DB에서 이름을 찾고 첫 인쇄판을 선택한다. 카드 ID 후보가 여럿이면 직접 고를 수 있다. 잘못된 구역·수량이나 찾을 수 없는 카드는 줄 번호와 함께 표시되며, 모든 줄을 확인한 후 덱을 저장한다.

### 카드 데이터 업데이트와 복구

설치된 DB는 카드 수정일과 인쇄판 수정일을 각각 조회한다. 두 날짜는 이전 성공 작업의 시작 시각보다 이틀 앞선 UTC 날짜다. 공식 카드 목록의 UUID와 slug를 대조하고 후보의 상세 데이터를 재조회한다. 변경이 없으면 카드 상세는 다운로드하지 않는다. 수정 시각이 소급되었거나 갱신되지 않은 변경은 **설정 → 데이터 관리 → 전체 데이터 재검사**로 확인한다.

양면 카드의 인쇄판 연결을 재구성해야 하거나 후보가 전체의 30% 이상이면 전체 수집으로 전환한다. 기존 공식 목록이 급격하게 줄어들면 반영을 중단한다. 다운로드를 취소하거나 검증에 실패해도 기존 덱과 스포일러를 유지한다. 사라진 인쇄판의 기존 덱 참조는 보존한다.

**데이터 관리 → 다운로드 상태**에서 단계와 완료 수를 확인한다. 중단된 작업은 **다운로드 재개**로 이어간다. 재개 시 조회 조건·인덱스·페이지 경계를 다시 확인하며 일치하지 않으면 해당 수집을 다시 시작한다. Android는 WorkManager, Windows는 앱 프로세스의 Isolate를 사용한다. Windows에서 앱을 종료한 경우 다음 실행에서 재개할 수 있다.

**동기화 기록**에서 최근 종료 작업 50개와 진행 중인 작업의 상태, 변경 수량, 요청 횟수, 수신량, 오류를 확인한다. 데이터 무결성 검사에서 손상이 보고되면 전체 재검사를 실행한다. 전체 백업을 복원한 경우 다음 업데이트에서 공식 DB 전체를 검증한다. 사용자 데이터만 복원하면 공식 DB의 동기화 기준을 유지한다.

### 카드 일러스트 테마

**설정 → 테마 선택**에서 설치된 공식 카드의 배너를 이름으로 검색하고 인쇄판별로 선택할 수 있다. 창 높이가 너비의 1.5배를 초과하면 `banner/tall.jpg`를 중앙에, 너비가 높이의 1.5배를 초과하면 `banner/wide.jpg`를 오른쪽에 맞춘다. 그 외에는 `icon/large.jpg`를 중앙에 맞춘다. 회전하거나 창 크기를 변경하면 같은 인쇄판에 등록된 이미지를 사용하며, 해당 이미지가 없거나 다운로드에 실패하면 저장된 기본 이미지를 표시한다. 다운로드와 디코딩이 끝나면 앱 배경에 적용하고 60% 검은색 오버레이를 덧댄다. **기본 테마**로 돌아갈 수 있다.

선택한 기본 이미지와 화면 비율에 맞춰 열람한 이미지, Edition·경로·버전·오버레이 값은 사용자 설정으로 DB에 보관한다. 일반 이미지 캐시를 삭제하거나 오프라인으로 재실행해도 선택을 유지하며, 사용자 백업과 전체 DB 백업에 포함된다. PNG 출력은 별도의 배경을 사용한다.

### 삭제·재설치 전 데이터 보관

설정의 **데이터 관리 → 사용자 데이터 백업**에서 앱 외부에 ZIP을 저장한다. 덱과 선택 인쇄판, 스포일러 사진, 사용자 설정이 포함된다. 공식 카드까지 오프라인에서 복구하려면 **전체 DB 백업**을 선택한다. 재설치 후 같은 종류의 복원을 선택한다. 미설치 카드의 UUID와 수량은 유지되며 공식 DB 설치 후 다시 이름과 인쇄판을 확인할 수 있다.

복원은 기존 데이터를 교체한다. 임시 DB에서 파일 해시, 레코드 수, 참조 및 무결성 검사를 통과한 뒤 요약을 확인하고, 기존 데이터의 복구용 ZIP을 다른 이름으로 저장하면 적용된다. 복구용 파일 저장을 취소하면 교체도 취소된다. ZIP에는 사용자 사진과 덱이 포함되며 암호화되어 있지 않다.

### Android 정식 업데이트 준비

운영자는 GitHub Environment **android-production**을 만든 뒤 배포 브랜치를 **main만 허용**으로 제한하고 승인자를 지정한다. 기존 배포용 키의 Base64를 환경 Secret `ANDROID_KEYSTORE_BASE64`에, 비밀번호·alias를 각각 `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`에 등록한다. 환경 변수 `ANDROID_CERT_SHA256`에는 기존 배포 인증서 SHA-256 지문(콜론 없이 64자리)을 등록한다. 키는 안전한 별도 장소에도 보관한다.

검토된 변경 병합 후 **Actions → Android signed release → main → Run workflow**로 시작한다. 서명 작업에는 소스 체크아웃이 없으며 검증된 APK만 결과물로 게시한다. 배포 버전명은 pubspec.yaml에서, versionCode는 워크플로 실행 번호 + 1000에서 온다. 재빌드는 새 실행으로 시작한다. 워크플로를 교체하거나 다른 경로에서 배포할 때에는 기존 최고 versionCode보다 큰 번호를 사용한다. PR의 debug APK는 테스트 전용이다.

동일한 applicationId·서명으로 더 높은 버전을 설치하면 Android가 앱 데이터와 DB를 유지한다. 최초 전환 때 서명이 다르면 기존 앱에서 외부 ZIP 백업을 확보한 뒤 재설치한다. **백업 기능이 없는 구버전**은 기존 앱과 같은 키로 서명한 백업 지원 빌드를 먼저 설치해야 앱 안에서 내보낼 수 있다. 실기기에서는 덱·스포일러·설정을 생성한 뒤 서명된 다음 빌드를 `adb install -r`로 설치하고 DB 최종 갱신일, 사진, 설정, 캐시를 확인한다.
